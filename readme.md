# TeamFinder

TeamFinder — веб-приложение для поиска участников в командные проекты.
Пользователи создают проекты, находят единомышленников, просматривают профили
и присоединяются к открытым проектам.

Итоговый учебный проект Яндекс Практикума, вариант № 2 — «Навыки пользователей»
(навыки пользователей и фильтрация участников по навыкам).

## Возможности

- Регистрация, вход по email и выход из аккаунта.
- Просмотр и редактирование профиля, смена пароля, автоматическая генерация аватара.
- Добавление и удаление собственных навыков с автодополнением.
- Список участников с фильтрацией по навыкам.
- Создание проектов, просмотр списка и подробной информации о проекте.
- Редактирование и завершение собственных проектов.
- Присоединение к открытым проектам и отказ от участия; автор остаётся участником.
- Пагинация списков проектов и участников по 12 записей.
- Управление пользователями, навыками и проектами через Django Admin.

## Технологии

Python 3.13 (локальная проверка — 3.13.14), Django 5.2.4, Django ORM,
PostgreSQL 16, Docker Compose, HTML, CSS и JavaScript.
Pillow используется для аватаров, python-decouple — для чтения настроек,
psycopg2-binary — для подключения к PostgreSQL.
Версии зависимостей зафиксированы в `requirements.txt`.

## Установка и запуск

Нужны Python 3.13, Git и Docker с поддержкой команды `docker compose`.
На Windows предварительно запустите Docker Desktop.
В Docker работает только PostgreSQL; Django запускается локально.
Команды ниже предназначены для Git Bash на Windows или Bash на Linux/macOS.
Все команды после клонирования выполняйте из папки с `manage.py`.

### 1. Клонирование и окружение

```bash
git clone https://github.com/cyberh0lly/team-finder-ad.git
cd team-finder-ad
python -m venv venv
```

Активируйте окружение одной из команд.

Windows Git Bash:

```bash
source venv/Scripts/activate
```

Linux и macOS:

```bash
source venv/bin/activate
```

Если в Linux/macOS Python доступен только как `python3`, используйте
`python3 -m venv venv` при создании окружения. После активации используйте `python`.

```bash
python -m pip install -r requirements.txt
cp .env.example .env
```

Копируйте пример только при первоначальной установке, чтобы не заменить свой `.env`.

### 2. Переменные окружения

Откройте `.env`. Замените `replace-with-your-secret-key` и `change-me` своими
значениями до запуска базы. Случайный ключ Django можно получить командой:

```bash
python -c "from django.core.management.utils import get_random_secret_key; print(get_random_secret_key())"
```

Скопируйте результат в `DJANGO_SECRET_KEY`. Не публикуйте его.
Настройки читаются из `.env` через python-decouple; переменные окружения процесса
имеют приоритет. Файл `.env` исключён из Git.

| Переменная | Назначение и значение для локального запуска |
|---|---|
| `DJANGO_SECRET_KEY` | Секретный ключ Django; сгенерируйте собственный |
| `DJANGO_DEBUG` | `True` для локальной разработки и отображения медиафайлов |
| `ALLOWED_HOSTS` | Разрешённые адреса через запятую: `localhost,127.0.0.1` |
| `POSTGRES_DB` | Название базы, в примере `team_finder` |
| `POSTGRES_USER` | Пользователь базы, в примере `team_finder` |
| `POSTGRES_PASSWORD` | Собственный пароль пользователя базы |
| `POSTGRES_HOST` | `localhost`: Django работает вне контейнера |
| `POSTGRES_PORT` | `5436`: порт PostgreSQL на компьютере |
| `TASK_VERSION` | `2`: шаблоны из `templates_var2/` |
| `DEMO_PASSWORD` | Общий пароль новых демопользователей; передаётся через терминал при заполнении базы |

Внутри контейнера PostgreSQL использует порт `5432`. Compose публикует его только
на `127.0.0.1` с портом из `POSTGRES_PORT`. Если порт 5436 занят, измените
`POSTGRES_PORT` в `.env` — этот параметр используют и Django, и Compose.
Названия настроек — именно `DJANGO_SECRET_KEY` и `DJANGO_DEBUG`, а не `SECRET_KEY` и `DEBUG`.

### 3. PostgreSQL и миграции

```bash
docker compose config --quiet
docker compose up -d
docker compose ps
```

Дождитесь статуса `healthy` у `teamfinder_db`, затем выполните:

```bash
python manage.py migrate
python manage.py createsuperuser
```

Для суперпользователя укажите собственные email, имя, фамилию и пароль.
Параметры `POSTGRES_DB`, `POSTGRES_USER` и `POSTGRES_PASSWORD` инициализируют базу
при первом запуске с пустым volume. Изменение `.env` не меняет пароль уже созданной базы.

### 4. Демонстрационные данные

Для локальной демонстрационной базы выполните команды ниже. Ввод пароля скрыт;
команда `seed_data` сама пароль не запрашивает.

```bash
read -s -p "Демонстрационный пароль: " DEMO_PASSWORD
echo
export DEMO_PASSWORD
python manage.py seed_data
unset DEMO_PASSWORD
```

`DEMO_PASSWORD` читается напрямую из окружения процесса: записи только в `.env`
недостаточно. Если пароль не задан или пуст, команда завершится с понятной ошибкой.
Пароль сохраняется в базе в виде хеша; заранее заданного пароля нет.

При свободных email создаются следующие обычные активные пользователи:

| Максим Иванов | maxim@example.com | Планировщик задач | Открыт |

Создаются навыки Python, Django, PostgreSQL, HTML, CSS, JavaScript, Git, Docker,
Figma и SQL. Они распределяются между пользователями; несколько участников
владеют одинаковыми навыками для проверки фильтрации. Аватары генерируются автоматически.
Авторы включаются в участники проектов, добавляются и участники чужих проектов.

Для входа используйте email из таблицы и пароль, введённый перед первым запуском.
Демопользователи не получают административных прав.
Повторный запуск не создаёт дубликаты и не меняет пароли или данные существующих
пользователей. Любой занятый email пропускается с предупреждением, даже если аккаунт
создан прошлым запуском команды. Удалённые или изменённые данные таких аккаунтов
команда не восстанавливает. В конце выводятся количества созданных и пропущенных записей.


Откройте [главную страницу](http://127.0.0.1:8000/).
Эта инструкция предназначена для локальной разработки и проверки проекта.

## Административная панель

Войдите по email и паролю суперпользователя, созданного командой
`python manage.py createsuperuser`. Через админку доступны пользователи, навыки
и проекты: можно менять права и пароли пользователей, назначать навыки,
редактировать проекты и участников. Доступ сотрудников ограничен разрешениями Django.

## Тесты

Запустите PostgreSQL и активируйте виртуальное окружение, затем выполните:

```bash
python manage.py check
python manage.py test
python manage.py makemigrations --check --dry-run
```

Тесты используют отдельную тестовую базу PostgreSQL. Пользователю базы требуется
право создавать тестовые базы; пользователь, созданный данным Docker Compose,
это право имеет. Проверяются регистрация, профили, пароли, навыки, фильтрация,
пагинация, проекты, права доступа, административная панель и повторный запуск `seed_data`.

## Остановка

Остановите Django сочетанием **Ctrl+C**, затем выполните:

```bash
docker compose down
```

Данные PostgreSQL сохраняются в именованном volume `postgres_data` между запусками.
Загруженные и сгенерированные аватары находятся локально в `media/` и не включаются в Git.

## Примечания для ревьюера

В документах `docs/` есть расхождения. По финальному чек-листу участники выводятся
от новых к старым, после регистрации выполняется переход на страницу входа без
автоматической авторизации. Выход выполняется через POST с CSRF-защитой.
Навыки связаны с пользователями через `ManyToManyField`. Телефон необязателен,
поскольку форма регистрации его не запрашивает; заполненный телефон проверяется
на формат и уникальность в форме редактирования профиля.
Избранное и необходимые навыки проектов относятся к другим вариантам и не реализованы.
